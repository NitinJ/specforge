# SpecForge 0.9.0: Codex preview

SpecForge now installs in Codex from the same release tree used by Claude Code
and Pi. Codex gets the canonical authoring, conversion, listing, review,
template, and export skills; stable thread ownership; Codex reply attribution;
and browser recovery prompts that reflect its actual delivery state.

The Codex CLI path is qualified on 0.153.4 with ChatGPT subscription
authentication and no OpenAI API key. The desktop package uses the same
manifest, hooks, and runtime, but remains a manual qualification gate.

Codex review delivery is a preview. Browser work is available on the next turn,
or immediately while the owning turn keeps `specforge review-wait` active in the
foreground. Native plugin hooks cannot wake a settled Codex thread, so this
release does not claim settled-thread parity with Claude Code or Pi.

Other changes in this release:

- one harness-neutral session, root, ownership, and delivery implementation;
- safe native thread IDs and isolated worker leases;
- read-only queue inspection with explicit pickup acknowledgements;
- idempotent agent replies across interrupted delivery;
- truthful **Listening**, **Review queued**, **Reviewing**, and
  **Disconnected** browser states;
- validated install, repeat update, rollback, and Codex-only removal;
- Node 18 runtime and Node 20/22 test contracts in CI.
