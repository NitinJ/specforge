# SpecForge components

Generated by `components build` from `components/` (library v1). Do not edit.

Every spec carries the component stylesheet as a stamped block, so these
classes are available in any spec and nothing needs importing. Pick a
component by asking what the block asserts. Appearance is never the entry
point: a notice takes a type, and its tone follows from the type.

## Choosing

| If the block asserts | Use |
|---|---|
| A choice was made between alternatives | `callout decision` |
| We believe X but have not verified it | `callout assumption` |
| This can fail in a specific way | `callout risk` |
| We are departing from a principle or an existing pattern | `callout deviation` |
| A limit exists that we cannot move | `callout constraint` |
| A number, with a method behind it | `evidence + src` |
| Several headline numbers at once | `stats` |
| Options weighed against each other | `table compare` |
| Items compared on attributes | `table` |
| An ordered procedure | `steps` |
| Conditions to verify in any order | `checklist` |
| A requirement that is normative | `kw` |
| A concrete instance of a rule | `callout example` |
| Somebody else’s words | `callout quote` |
| Something that will break if ignored | `callout danger` |
| Something to be careful about | `callout warning` |
| Context, no claim | `callout note` |
| Nodes and the relationships between them | `pre[data-lang="mermaid"]` |
| A picture where the exact placement carries meaning | `flow or figure, inline SVG` |
| Anything that must reflow at the reader’s width | `table, grid, card, steps` |
| None of the above | `a paragraph` |

**Density.** A component is emphasis, and emphasis is a budget. No more than
one notice per 400 words of a section, and never two notices in immediate
succession: two adjacent notices are a table with two rows.

## Drawing

Three ways, and the choice is not about how the result looks.

| If the diagram is | Use | Because |
|---|---|---|
| A graph: nodes and the relationships between them. Flowchart, sequence, state, ER, class. | `pre[data-lang="mermaid"]` | The relationships are the content and the position is not. Editable in one line, and it survives markdown as source. |
| A picture where position carries meaning: a timeline to scale, a screen layout, an annotated arrangement, or anything with no matching mermaid diagram type. | `.flow` or `figure` with inline SVG | Mermaid computes layout and will not honour a specific placement. Costs a sidecar file on export. |
| Not a diagram: a comparison, a grid of peer items, a UI mock, anything that must reflow at the reader’s width. | `table`, `.grid`, `.card`, `.steps` | A diagram of a table is a table drawn badly, and these reflow, which no SVG does. |

**Mermaid is the default for a graph.** An inline SVG of the same graph costs a coordinate for every node and every edge endpoint, has to be recomputed to move one box, and leaves the spec as a linked `.svg` file on export. A mermaid diagram is the same text at both ends and renders natively on GitHub.

**Past about 15 nodes a mermaid diagram stops being readable** at a spec’s column width. Split it, or say the same thing in a table. Asserted from the content width, not measured against readers.

**`mermaid` is the one declared language that is never highlighted**, and the one case where declaring a language on a block that is not code is correct. The rule against declaring a language on ASCII diagrams and pseudo-code is unchanged: those stay undeclared.

**A diagram is one comment target.** A reviewer comments on the diagram, not on a node inside it, so a picture carrying several separate claims is several diagrams or a table.

**It renders where the review layer runs**: the daemon and a published copy. From `file://` a diagram shows its source as a code block, the same trade the themes and the highlighter already make.

## Notices

### `.callout.note` · neutral

Context a reader needs that is not itself a claim about the design.

```html
<div class="callout note">Context a reader needs that is not itself a claim about the design.</div>
```

### `.callout.tip` · positive

Advice that makes something easier and is safe to ignore.

```html
<div class="callout tip">Advice that makes something easier and is safe to ignore.</div>
```

### `.callout.success` · positive

A settled good outcome: a check that passed, a target that was met.

```html
<div class="callout success">A settled good outcome: a check that passed, a target that was met.</div>
```

### `.callout.warning` · caution

A hazard the reader can avoid by knowing about it.

Must contain: what to do instead.

```html
<div class="callout warning">A hazard the reader can avoid by knowing about it.</div>
```

### `.callout.danger` · critical

An action that breaks something irreversibly.

Must contain: what breaks; whether it is recoverable.

```html
<div class="callout danger">An action that breaks something irreversibly.</div>
```

### `.callout.example` · neutral

A concrete instance of a rule stated elsewhere.

Must contain: a reference to the rule.

```html
<div class="callout example">A concrete instance of a rule stated elsewhere.</div>
```

### `.callout.quote` · neutral

Words that are somebody else’s, with attribution.

Must contain: attribution.

```html
<div class="callout quote"><p>The port is the singleton.</p><p class="footnote">PR #123</p></div>
```

### `.callout.decision` · neutral

A choice made, with the criterion it was made on.

Must contain: the criterion; the alternative not taken.

```html
<div class="callout decision">The port is the singleton. <strong>Criterion:</strong> a lockfile cannot be released on SIGKILL. <strong>Not taken:</strong> a pid file with a liveness probe.</div>
```

### `.callout.assumption` · caution

Something believed but not verified.

Must contain: what would falsify it.

```html
<div class="callout assumption">34 components cover what specs need. <strong>Falsified by:</strong> an author reaching for a class outside the registry.</div>
```

### `.callout.risk` · caution

A specific way this can fail, named precisely enough to design against.

Must contain: the trigger; the consequence.

```html
<div class="callout risk">The stamped block is hand-edited. <strong>Trigger:</strong> styling a one-off inside the markers. <strong>Consequence:</strong> the next sync overwrites it.</div>
```

### `.callout.deviation` · critical

A departure from a stated principle, house rule, or existing pattern.

Must contain: a quote of what is departed from; why.

```html
<div class="callout deviation"><strong>Departs from:</strong> the quoted rule. <strong>Why:</strong> the reason.</div>
```

### `.callout.constraint` · neutral

A fixed limit the design works within and cannot change.

Must contain: the limit; its unit; where it comes from.

```html
<div class="callout constraint">A spec renders from file:// with no network. <strong>Source:</strong> house rules, Format.</div>
```

## Inline

### `.tag`

Labelling a state or category inside a table cell, a heading, or a list item.

Variants: `accent`, `good`, `warn`, `bad`, `todo`, `done`.

```html
<span class="tag good">chosen</span>
```

### `.kw`

A normative keyword in a requirement, so a reader can tell a rule from a suggestion.

Must contain: one of MUST, MUST NOT, SHOULD, SHOULD NOT, MAY.

```html
A component <span class="kw">MUST</span> carry a type.
```

### `.term`

First use of a term the spec defines. Defined once, referenced thereafter.

Must contain: a title attribute carrying the definition.

```html
<span class="term" title="A spec's generated component stylesheet.">stamped block</span>
```

### `.footnote`

An aside that would interrupt the sentence carrying it.

```html
<p class="footnote">Authored with SpecForge</p>
```

### `.src`

Attribution for a measured or cited value. Satisfies the language contract’s source sentence.

Must contain: the source; a retrieval date.

```html
<span class="src">audit-specforge-callouts.mjs, 2026-08-14</span>
```

### `<code>`

An identifier, path, flag, or literal value. Never used for emphasis.

```html
<code>lib/config.mjs</code>
```

### `<kbd>`

A key the reader presses.

```html
<kbd>Ctrl</kbd>
```

## Data

### `<table>`

Three or more items compared on two or more attributes. Fewer is a sentence.

Must contain: a thead.

```html
<table><thead><tr><th>Option</th><th>Cost</th></tr></thead><tbody><tr><td>A</td><td>8 KB</td></tr></tbody></table>
```

### `.compare`

Options weighed against each other, where the point of the table is the verdict.

Must contain: a final verdict column carrying a tag.

```html
<table class="compare"><thead><tr><th>Option</th><th>Verdict</th></tr></thead><tbody><tr><td>A</td><td><span class="tag good">chosen</span></td></tr></tbody></table>
```

### `.stat`

Three to six headline numbers a reader should absorb before the prose.

Must contain: a number; a unit; a label.

Variants: `stats`, `n`, `k`.

```html
<div class="stats"><div class="stat"><span class="n">669</span><span class="k">classes in use</span></div></div>
```

### `<dl>`

Terms with definitions, where the term is the thing being looked up. Preferred over a two-column table for a glossary.

```html
<dl><dt>Stamped block</dt><dd>The generated component CSS between the markers.</dd></dl>
```

## Code

### `.codeblock`

Code or configuration a reader will copy, or compare against a file on disk.

Must contain: a filename caption when the code corresponds to a path.

Variants: `filename`.

```html
<div class="codeblock"><span class="filename">lib/config.mjs</span><pre><code>export const PALETTE_TOKENS = [];</code></pre></div>
```

### `.diff`

A change to existing code, where the before matters as much as the after.

Must contain: added and removed lines marked.

Variants: `add`, `del`, `ctx`.

```html
<div class="diff"><span class="del">- old line</span><span class="add">+ new line</span></div>
```

## Structure

### `.panel`

A block that stands apart from the flow and is read as a unit. The TL;DR is a panel.

```html
<div class="panel"><p>Read as a unit.</p></div>
```

### `.card`

One of three or more peer items of the same kind, each a few lines. Use inside a grid.

Variants: `grid`.

```html
<div class="grid"><div class="card">One</div><div class="card">Two</div></div>
```

### `.steps`

An ordered procedure where the order is load-bearing. One action per step.

Must contain: each item is an action.

```html
<ol class="steps"><li>Write the failing test.</li><li>Make it pass.</li></ol>
```

### `.checklist`

Conditions to verify, in any order. If the order matters it is steps.

Must contain: independent, checkable items.

Variants: `ok`.

```html
<ul class="checklist"><li class="ok">Tints derive from a token</li><li>Registry agrees</li></ul>
```

### `<figure>`

Any diagram or image. The caption states what the reader should conclude, not what the picture contains.

Must contain: a figcaption.

```html
<figure><svg viewBox="0 0 220 48" role="img" aria-label="A spec, stamped and served">
  <rect class="svg-box" x="1" y="8" width="96" height="32" rx="8"/><text class="svg-lbl" x="49" y="28" text-anchor="middle">spec</text>
  <path class="svg-arrow" d="M100 24 H124"/>
  <rect class="svg-box-a" x="124" y="8" width="94" height="32" rx="8"/><text class="svg-lbl" x="171" y="28" text-anchor="middle">stamped</text>
</svg><figcaption>The lint runs on the stamped file, so what is checked is what is served.</figcaption></figure>
```

### `pre[data-lang="mermaid"]`

A graph: nodes and the relationships between them, where the layout follows from the relationships rather than from where you put things. Flowchart, sequence, state, ER, class.

Must contain: mermaid source, and no hand-placed coordinates.

```html
<pre data-lang="mermaid"><code>flowchart LR
  A[collector] --&gt; B{queue full?}
  B -- yes --&gt; C[retry queue]
  B -- no --&gt; D[(store)]</code></pre>
```

### `.flow`

A sequence of stages over time or through components, where the exact placement carries meaning. If the layout follows from the relationships, use mermaid instead. Inline SVG, nodes and edges from palette tokens.

Must contain: an aria-label saying what the diagram shows.

Variants: `svg-box`, `svg-box-a`, `svg-lbl`, `svg-lbl-m`, `svg-arrow`.

```html
<div class="flow"><svg viewBox="0 0 330 48" role="img" aria-label="authored, then stamped, then linted">
  <rect class="svg-box" x="1" y="8" width="94" height="32" rx="8"/><text class="svg-lbl" x="48" y="28" text-anchor="middle">authored</text>
  <path class="svg-arrow" d="M98 24 H120"/>
  <rect class="svg-box-a" x="120" y="8" width="94" height="32" rx="8"/><text class="svg-lbl" x="167" y="28" text-anchor="middle">stamped</text>
  <path class="svg-arrow" d="M217 24 H239"/>
  <rect class="svg-box" x="239" y="8" width="90" height="32" rx="8"/><text class="svg-lbl" x="284" y="28" text-anchor="middle">linted</text>
</svg></div>
```

## Spec structure

### `.sf-stages`

The implementation plan. One stage is one PR; each task carries a verify note.

Must contain: data-sf-stage; data-sf-task; data-sf-status.

Variants: `sf-tasks`, `sh`, `verify`.

```html
<ol class="sf-stages"><li data-sf-stage="1"><div class="sh"><h3>Stage 1: Name</h3></div><ul class="sf-tasks"><li data-sf-task="1.1" data-sf-status="todo">Task<span class="verify">verify: how</span></li></ul></li></ol>
```

### `li[data-sf-q]`

An unresolved question. While one is open the pre-implementation gate refuses to start.

Must contain: data-sf-q of open, resolved, or dropped.

```html
<ul><li data-sf-q="open"><strong>Q1 — <span class="tag warn">open</span></strong> The question.</li></ul>
```

### `.evidence`

A claim that rests on a measurement or an external source.

Must contain: the value; the method; the retrieval date; a confidence.

Variants: `val`, `meta`.

```html
<div class="evidence"><p class="val">338 classes</p><p class="meta">Method: parse every spec.html · n=111 · 2026-08-14</p></div>
```
